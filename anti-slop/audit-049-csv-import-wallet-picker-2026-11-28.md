## Cakupan

Tugas Gelombang 7c Item 4: saat impor CSV bank, transaksi masuk tanpa pengguna bisa memilih dompet tujuan. Pekerjaan dibatasi pada `web/transaction-import.js` + UI impor terkait + tes. Tidak menyentuh modul sync/offline, delete-account, webauthn, `web/ui-feat-native-ux.js`, atau `web/config.js`. Tidak ada jalur tulis transaksi baru: baris hasil impor tetap dikirim lewat `api_importTransactions` yang sudah ada (jalur simpan + validasi yang sama), perubahan hanya pada penentuan dompet sebelum simpan. Pekerja lain sedang mengubah jalur sync (optimistic locking) — API tulis transaksi tidak diubah.

## Temuan / Akar Masalah

Pemetaan alur impor (dibaca penuh sebelum mengubah apa pun):

- **Pemicu UI**: Laporan → menu "Impor & Aturan" → tombol `#lapImportBtn` (`src/laporan.html:28`) → `bindReportControls` di `web/ui-reports.js:227` langsung membuka pemilih file `#lapCsvInput` → `change` → `importTransactionsCsv(file)` → `TransactionImport.parseTransactionCsv(text, DB.transactions, DB.wallets, importOptions)` → pratinjau Swal → konfirmasi → `callServer('api_importTransactions', result.valid)` → `refreshFromServer(response)`.
- **Transaksi hasil impor masuk ke dompet mana (hari ini)?** Dompet **pertama dalam daftar** `DB.wallets` (`wallets[0]`, urutan sort/nama dari server) — bukan dompet utama bank, bukan pilihan pengguna. Bukti: `parseTransactionCsv` mengisi `ctx.defaultWalletId = walletList[0].id` dan `parseCsvDataRow` memakai nilai itu untuk setiap baris tanpa kolom dompet. Setting `primaryBankWalletId` (PR #2, dompet utama bank untuk runway) sama sekali tidak dibaca di jalur impor. Jadi mutasi BCA yang diimpor pengguna dengan dompet utama "BCA" tapi `wallets[0]` = "Cash" masuk ke Cash — dan saldo runway ikut salah arah.
- **Pemetaan kolom terjadi di mana?** `resolveCsvColumns` (`web/transaction-import.js`): header dinormalisasi lowercase lalu dicocokkan ke kandidat — tanggal (`tanggal/date/tgl/posting date/transaction date`), tipe, kategori, nominal, debit/kredit, keterangan, dompet (`dompet/nama_dompet/wallet`). `findHeaderRowIndex` mencoba 30 baris pertama sampai satu baris lolos `resolveCsvColumns` (ini yang membuat preamble rekening bank dilewati). Pemetaan ini **tidak berubah** dalam item ini.
- **Batas 500 baris ditegakkan di mana?** Di parser, `parseTransactionCsv`: `parsedRows.length > MAX_DATA_ROWS` (500) → throw menyebut jumlah baris data setelah header. Batas kedua ada di server: `api_importTransactions` (`web/supabase-records.js:140`) menolak `items.length > 500`. UI hanya membatasi ukuran file (2 MB). Batas 500 **tetap berlaku dan dites** dalam item ini.
- **Pengecualian yang sudah ada dan dipertahankan**: bila CSV **punya kolom dompet**, tiap baris memakai dompet dari file — sel kosong → error per baris (§9c), nama tak dikenal → error per baris. Bila CSV **tidak punya** kolom dompet (semua mutasi bank), semua baris memakai satu dompet default. Komentar lama di kode menyebut penyimpangan §9c ini secara sadar dan meminta pemilih dompet di UI impor sebelum aturan itu bisa diperketat — item ini adalah penutupnya.
- **Jalur simpan yang sudah ada**: `api_importTransactions` (`web/supabase-records.js:140`) memvalidasi tiap baris (`trxRow`), menolak kategori/dompet asing terhadap data milik pengguna, mendeduplikasi (fingerprint memakai `walletId`), lalu satu `insert` dengan `source: 'import'`. Fingerprint-nya memakai `defaultWalletId` (dompet pertama server) hanya sebagai fallback bila `wallet_id` kosong — tidak mengubah dompet tujuan. Item ini tidak menyentuh fungsi ini sama sekali.

## Perubahan yang Diterapkan

1. **`web/transaction-import.js` (+60/−13, 2 fungsi baru + 1 return diperluas)**:
   - `resolveDefaultImportWalletId(wallets, primaryBankWalletId)` — diekspor, dipakai UI dan parser dari satu sumber: dompet utama bank bila id-nya cocok dengan dompet di daftar **dan** berjenis `bank`; bila tidak ada/tidak valid (terhapus, bukan bank, bukan string, kosong) → `wallets[0]` (perilaku lama); bila tidak ada dompet sama sekali → `''`.
   - `resolveImportTargetWallet(wallets, options)` — diekspor: pilihan eksplisit `options.targetWalletId` yang valid menang atas default; pilihan tidak valid → fallback ke default + `walletFallback: { requested, used }` (bukan gagal diam-diam, bukan dompet yang salah).
   - `parseTransactionCsv(text, existing, wallets, options)` kini menerima `options.targetWalletId` dan `options.primaryBankWalletId`; mengembalikan tambahan `targetWalletId` (dompet efektif), `walletFallback` (`null` atau `{ requested, used }`), dan `hasWalletColumn` (apakah file punya kolom dompet). Tanpa options sama sekali → hasil identik dengan perilaku lama (`wallets[0]`). Parsing/pemetaan kolom, validasi per baris (§9b/§9c/§9d/§9e/§10), dedup, dan batas 500 baris tidak berubah. Komentar §9c yang lama ("perlu pemilih dompet di UI impor") diperbarui: pemilih itu kini ada.
   - **Pengecualian yang didokumentasikan**: bila file punya kolom `dompet`, dompet per baris dari file tetap menang atas pilihan di pemilih — pilihan hanya mengatur baris tanpa dompet sendiri. Alasannya: template CSV resmi (`downloadTransactionTemplate`) memang memakai kolom dompet per baris; menimpa nilai eksplisit dari file dengan satu dompet pilihan akan memindahkan transaksi ke dompet yang salah. Pratinjau impor menampilkan catatan ini bila file punya kolom dompet.
2. **`web/ui-reports.js` (+91/−13)**:
   - `promptImportWallet()` (baru, diekspor): dialog Swal **sebelum** pemilih file dibuka — label + `<select id="csvImportWalletSelect">` berisi semua dompet pengguna lewat `walletOptions(defaultId, true)`, format yang sudah dipakai di tempat lain (nama + jenis + saldo berjalan, pola U11; label jenis `walletKindLabel` tetap Bahasa Indonesia seperti pemakaian `walletOptions` lainnya — bukan cakupan item ini). Default terpilih = dompet utama bank bila valid, bila tidak dompet pertama. Batal di dialog = tidak ada impor sama sekali. Bila belum ada dompet → error `lap.import_no_wallet`, impor tidak jalan.
   - `resolveImportWalletDefault()` (baru, diekspor): memakai `TransactionImport.resolveDefaultImportWalletId` bila tersedia, dengan fallback lokal yang sama.
   - `bindReportControls`: klik `#lapImportBtn` kini `await promptImportWallet()` dulu, menyimpan pilihan di `pendingImportWalletId`, baru membuka pemilih file; `change` meneruskan pilihan itu ke `importTransactionsCsv(file, walletId)` lalu mengosongkannya.
   - `importTransactionsCsv(file, selectedWalletId)`: meneruskan `targetWalletId` + `primaryBankWalletId` ke parser. Pratinjau kini menampilkan baris "Dompet tujuan: <nama>" dan, bila terjadi fallback, peringatan kuning `lap.import_wallet_fallback` + nama dompet pengganti; bila file punya kolom dompet, catatan `lap.import_wallet_per_row`.
   - **Jalur simpan tidak berubah**: satu-satunya pengiriman tetap `callServer('api_importTransactions', result.valid)` — tidak ada `api_addTransaction`, tidak ada jalur tulis baru (dikunci tes).
