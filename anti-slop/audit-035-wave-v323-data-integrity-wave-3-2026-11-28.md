## Temuan Forensik

- **3.1 Auth/profil (S1–S7)**: challenge WebAuthn dibuat lalu dibuang tanpa verifikasi server (jalur native Android sehat); OAuth native tidak memvalidasi `state` dan menerima `access_token`/`refresh_token` mentah dari deep link lewat `setSession()` (login CSRF — risiko tertinggi); profil hilang fail-open lewat cache offline, peran `admin` dari cache dipercaya tanpa batas waktu; auto-lock hanya saat tab tersembunyi, tidak pernah saat inaktivitas terlihat; kebijakan kata sandi hanya panjang (`aaaaaaaa` lolos); hash PIN lawas tanpa salt masih diterima tanpa batas waktu; `derivePinHash()` punya bug fallback (mengembalikan hex polos bila prefix tidak cocok).
- **3.2 Database (S8–S13)**: `is_admin()` versi final sudah benar di repo (hanya butuh verifikasi produksi); sisa OTP — SHA-256 tanpa salt atas kode 8 digit, tanpa batas laju pembuatan, lookup webhook global untuk fallback bot bersama; audit log terbuka untuk pemalsuan (INSERT langsung, tanpa allowlist aksi di `admin_log_action()`, tanpa trigger append-only); `prevent_admin_lockout()` punya cabang DELETE yang lolos lewat `service_role` (risiko tertinggi); tidak ada riwayat perubahan aset/goal sama sekali, jalur dompet NULL tidak meninggalkan jejak; `create_asset_with_expense()` menolak negatif hanya untuk Crypto (Saham/Cash/Other menyimpan negatif; tanpa CHECK di `assets`).
- **3.3 Edge function (S14–S19)**: CORS fail-open ke `*` di semua 5 fungsi; `telegram-setup` membaca env `ALLOWED_ORIGINS` yang namanya berbeda; kunci CoinGecko di query string; `currency-api` di `@latest`; reset kata sandi admin tanpa audit log dan tanpa notifikasi pemilik (risiko tertinggi); tidak ada batas atas nominal; tanggal `/batch` Telegram tidak divalidasi kalender, tanpa batas baris; recurring dicocokkan dari prefix (`planning.ts:175`, destruktif); transfer tanpa cek saldo; Gemini tanpa rate limit preventif.
- **3.4 Frontend/CDN/build (S24–S25)**: nol atribut `integrity` di mana pun (11 pemuatan eksternal di `src/styles.html`); `fetch-vendors.mjs` tanpa verifikasi hash vendor (lubang cache-skip: vendor beracun yang ter-cache dipercaya selamanya); fallback CDN diam-diam di mana-mana termasuk satu-satunya `document.write` di repo (fallback Supabase, `build.mjs:106-112`); checkout baru tidak punya `web/vendor/` (gitignored) tapi tetap berhasil build — sepenuhnya bergantung CDN; build PR di CI melewatkan langkah fetch vendor.
- **3.5 Restore/transfer/antrean (S26–S39)**: export menulis 10 koleksi tapi restore hanya membaca 8 (transfer + entities hilang); dompet tidak cocok diam-diam di-re-home ke dompet pertama (tiga fallback bertumpuk); restore tidak atomik; tanda tangan dedup menelan kopi harian yang identik (tanpa dompet/waktu/id); pemilik snapshot tidak pernah diverifikasi (nama tampilan, bukan UID), tanpa kedaluwarsa; tidak ada RPC transfer atau cek saldo; antrean offline hanya 4 op, urutan tidak dijamin, `api_savePeriod` memalsukan sukses saat error jaringan; backup PBKDF2 150.000 iterasi, minimum 6 karakter (decrypt mengabaikan `iterations` yang tersimpan — jebakan back-compat); batas 500 baris CSV hanya di UI, bukan parser; sebagian besar validasi tulis hanya di klien.
