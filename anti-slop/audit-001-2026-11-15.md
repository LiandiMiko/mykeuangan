# Audit 001 - 2026-11-15

## Cakupan dan verifikasi

Meninjau alur panel admin, autentikasi profil, pairing Telegram, kebijakan RLS, dan kontrol reset demo pada source aplikasi.

`node build.mjs` berhasil. Belum ada uji runtime dengan akun Supabase, sehingga error yang tampil di panel admin belum dapat direproduksi langsung.

## Temuan

### 1. [P1] Hapus kontrol reset data demo (R-26)

`src/Index.html` menampilkan tombol yang memanggil `resetDemo()`, tetapi `web/supabase-api.js` membuat `api_resetDemo()` selalu gagal. Penanganan di `src/script.html` hanya mencatat error ke console, sehingga tombol tidak melakukan aksi yang berguna. Hapus tombol dan alur reset yang tidak dipakai.

### 2. [P1] Tampilkan kegagalan pemuatan panel admin (R-27)

`loadAdminData()` di `src/script.html` hanya mencatat kegagalan ke console dan membiarkan baris “Memuat data pengguna...” tetap tampil. Di `api_getAdminData()`, error dari query hitung chat Telegram juga tidak diperiksa, sehingga kegagalan query dapat terlihat sebagai angka nol. Tampilkan status error yang bisa dilihat admin dan teruskan error query dengan jelas.

### 3. [P1] Batasi perubahan role dan status profil di RLS

Policy `users_update_own_profile` pada `supabase/migrations/20261114000000_multiuser_onboarding.sql` mengizinkan pengguna memperbarui baris profil miliknya sendiri tanpa membatasi kolom. Akibatnya, pengguna dapat mengubah `role` menjadi `admin` langsung lewat API, melewati panel admin. Ubah kebijakan agar hanya admin yang dapat mengubah `role` dan `status`.

### 4. [P1] Lengkapi data wajib saat membuat pairing Telegram (R-26)

`telegram_pairings.user_id` diwajibkan oleh `supabase/migrations/20261114000001_telegram_pairings.sql`, tetapi `api_generateTelegramOTP()` di `web/supabase-api.js` hanya mengirim `{ otp }`. Pembuatan kode akan gagal karena `user_id` tidak diberikan. Isi `user_id` dari sesi terautentikasi atau tetapkan default `auth.uid()` pada skema.

### 5. [P2] Jangan menelan kegagalan membaca profil saat login (R-27)

`finishLogin()` di `web/supabase-api.js` mengabaikan error query profil dan hanya mencatat exception. Jika profil gagal dibaca, role tetap pada nilai default dan tautan admin tidak muncul, tanpa pesan yang menjelaskan penyebabnya. Tampilkan/propagasikan kegagalan tersebut dan bedakan profil yang tidak ditemukan dari kegagalan query.

### 6. [P2] Tegaskan cakupan angka “Bot Terhubung”

Query hitung `telegram_chats` di `api_getAdminData()` mengikuti policy “own rows” di `db/schema.sql`. Karena itu angka yang tampil di admin hanya menghitung chat milik admin yang sedang login, bukan seluruh pengguna. Sesuaikan definisi metrik atau labelnya supaya cakupannya tidak menyesatkan.

### 7. [P1] Pastikan hanya akun pertama yang mendapat role admin

Trigger onboarding di `supabase/migrations/20261114000000_multiuser_onboarding.sql` dapat memberi role admin ke dua pendaftar bersamaan, dan backfill lama memberi role admin ke semua akun yang sudah ada. Serialisasikan trigger dan batasi backfill ke akun paling awal. Database yang sudah menjalankan backfill perlu ditinjau manual sebelum role tambahan diturunkan.

### 8. [P2] Izinkan pengguna memperbesar tampilan (R-39)

Meta viewport di `src/Index.html` menetapkan `maximum-scale=1` dan `user-scalable=no`, sehingga pengguna tidak dapat memperbesar halaman. Hapus pembatasan zoom agar konten tetap dapat dibaca pada pembesaran.
